# Módulo: Empresa

## Objetivo

Consolidar o contexto da empresa vinculada ao usuário autenticado, permitindo que o Geitus exiba a empresa atual no layout e ofereça uma tela simples para consultar e alterar o nome da empresa.

## Escopo (Etapa 6 — contexto inicial da empresa)

- Exibir a empresa vinculada ao usuário autenticado.
- Expor os endpoints mínimos:
  - `GET /api/empresas/minha`
  - `PATCH /api/empresas/minha`
- Permitir alterar apenas o nome da empresa.
- Exibir o nome da empresa no layout autenticado.
- Criar página protegida de Empresa no frontend.

## Fora do escopo

- CRUD completo de empresas.
- Gestão de usuários.
- Convites de usuários.
- Multiempresa avançado ou troca de tenant.
- Perfis/permissões avançadas.
- Dados fiscais, endereço completo, logo/upload de marca ou configurações comerciais avançadas.

## Decisões relacionadas

- **DEC-015** — PK interna `BIGINT GENERATED BY DEFAULT AS IDENTITY` / `Long`.
- **DEC-016** — Usuários nascem vinculados a uma empresa/tenant por `empresa_id`.

## Endpoints

### `GET /api/empresas/minha` (autenticado)

Retorna a empresa vinculada ao usuário autenticado.

Regras:

- Não recebe `empresaId` por path, query ou body.
- A empresa é sempre derivada do usuário autenticado pelo JWT.
- Retorna 401 quando não houver token válido.

### `PATCH /api/empresas/minha` (autenticado)

Atualiza dados básicos da empresa vinculada ao usuário autenticado.

Request:

```json
{ "nome": "Mercado Central" }
```

Regras:

- Permite alterar apenas `nome`.
- `nome` é obrigatório.
- Não permite alterar `id`, `ativo`, `criadoEm`, `atualizadoEm` ou empresa de outro usuário.

## Modelo de dados atual

Reusa a tabela `empresa` criada na autenticação inicial (`V2__auth_inicial.sql`).

Campos expostos na resposta:

- `id`
- `nome`
- `ativo`
- `criadoEm`
- `atualizadoEm`

Não há migration nova nesta etapa.

## Regras de segurança

- Todas as rotas de empresa exigem autenticação.
- A empresa manipulada é sempre resolvida a partir do usuário autenticado.
- Nenhum endpoint aceita identificador de empresa externo.
- Entidades JPA não são expostas diretamente; a API usa DTOs.
- Usuário inexistente ou inativo é tratado como não autenticado.

## Regras de UX

- A tela de Empresa deve ser simples e focada no essencial.
- O layout autenticado deve mostrar o nome da empresa de forma discreta.
- O formulário deve tratar loading, erro, validação e sucesso.
- Feedbacks devem ser claros e discretos.

## Critérios de aceite

- `/api/empresas/minha` sem token retorna 401.
- `GET /api/empresas/minha` com token válido retorna a empresa do usuário autenticado.
- `PATCH /api/empresas/minha` valida nome obrigatório.
- `PATCH /api/empresas/minha` altera somente a empresa do usuário autenticado.
- `/api/auth/me` continua funcionando e retorna o contexto de empresa.
- A página de Empresa exige autenticação.
- A página exibe dados básicos da empresa.
- O formulário valida nome obrigatório e exibe feedback de sucesso/erro.

## Limitações conhecidas

- Não há histórico de alteração do nome da empresa.
- Não há dados fiscais, endereço, logo ou gestão de usuários.
- Não há suporte a múltiplas empresas por usuário.
- A resposta de empresa expõe apenas dados básicos.

## Próximos passos futuros

- Evoluir o módulo Empresa apenas quando houver especificação própria.
- Integrar a empresa aos próximos módulos operacionais sem implementar multiempresa avançado.
